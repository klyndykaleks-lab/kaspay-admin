# Каталог товаров и категории

## Назначение и согласование

Владелец проверил и согласовал поведение прототипа Lovable. Этот документ фиксирует согласованную работу раздела для разработчиков, продукт менеджера и будущей пользовательской инструкции. Эталон поведения: https://id-preview--96356608-f6d4-4596-8385-7c7ae9f2d71a.lovable.app/products. Зафиксированная версия прототипа: `2e5252ec97de297c3422fcca257a74fe2741d2df`.

Раздел содержит две вкладки: «Каталог товаров» и «Категории». Создание товара регистрирует справочную карточку. Остатки, закупочные и продажные цены, склад, накладная, скидки и налоги задаются в соответствующих операциях других разделов. Создание карточки само по себе не создаёт поступление, продажу, движение остатков или денежную проводку.

## Каталог товаров

Столбцы: Фото → Штрихкод → Полное название → Категория → Короткое название → Действия. Отдельных столбцов КБЖУ и статуса нет. «Нет фото» располагается по центру блока изображения.

Поиск — частичное совпадение по полному названию, короткому названию, категории или штрихкоду, без учёта регистра и пробелов по краям. Поля объединяются условием ИЛИ. Фильтр состояния «Активные / Неактивные / Все» действует одновременно с поиском. По умолчанию показаны активные товары. Данные разбиты на страницы по 10, 20 или 50 строк, отображаются диапазон и общее количество. Изменение поиска, фильтра или размера страницы возвращает на первую страницу; после удаления номер страницы корректируется.

Действия: редактирование → переключатель активности → удаление. Отключение товара требует подтверждения; отмена сохраняет прежнее состояние. Неактивный товар сохраняется в справочнике и доступен через фильтр. Включение возвращает активность. Во время записи повторное действие недоступно; при ошибке старое состояние сохраняется и показывается сообщение.

Удаление и отключение — разные операции. Удаление требует подтверждения. При наличии связей с учётом разработчики должны блокировать физическое удаление и предложить отключение, сохранив историю. Согласование этого ограничения с существующими связями БД входит в техническую приёмку.

## Карточка товара

| Поле | Обязательность | Правило |
| --- | --- | --- |
| Полное название | Да | Название из накладной; допускается длинный текст в пределах текущего лимита БД 512 символов |
| Короткое название | Да | Название для выбора покупателем на терминале; не заменяется полным названием |
| Штрихкод | Да | Основной критерий поиска товара; строка с сохранением ведущих нулей; текущий лимит БД 16 символов |
| Категория | Да | Выбор существующей активной категории; ранее назначенная неактивная категория сохраняется при редактировании |
| Вес в граммах | Нет | Пустое значение допустимо; если задан, не меньше 1 г |
| Единица учёта | Значение по умолчанию | ШТ / МЛ / ГР; по умолчанию ШТ |
| Страна | Нет | Для нового товара Беларусь; можно очистить; редактирование не подставляет страну заново |
| Состав | Нет | Текст, может быть пустым |
| Калории | Нет | ккал на 100 г; пустое значение равно 0 |
| Белки, жиры, углеводы | Нет | Граммы на 100 г; пустое значение равно 0; неотрицательные значения, дробная часть сохраняется |
| Фото | Нет | jpeg, jpg, png; до 1 MB = 1 048 576 байт; ширина и высота не больше 150 пикселей |

Пустое обязательное поле или строка из пробелов блокируют сохранение. Дубликат штрихкода среди активных и неактивных товаров запрещён; собственная карточка при редактировании исключается. Совпадение полного названия выводит предупреждение, но само по себе не запрещает сохранение.

Все изменения до «Сохранить» являются черновиком. Удаление или замена фото применяется только при успешной записи. Отмена, крестик и Escape отбрасывают черновик и возвращают исходную карточку с исходным фото. Под изображением всегда показаны размер, разрешение и форматы. Большие изображения отклоняются; автоматическое уменьшение и обрезка не выполняются. Старые фото не удаляются из-за нового ограничения.

Пока фото проверяется или форма сохраняется, повторная отправка недоступна. Ошибка фото блокирует запись; можно выбрать корректный файл или отменить неудачную загрузку. Ошибка сохранения оставляет форму открытой, сохраняет введённые данные и показывает причину. Успех записи закрывает карточку и обновляет список.

## Категории

Столбцы: Название → Описание → Действия. Фильтр «Активные / Неактивные / Все», по умолчанию активные. Поиск по названию и описанию сочетается с фильтром; видны количество результатов и сообщение при пустом результате.

В форме название обязательно, описание необязательно. Новая категория активна по умолчанию. Переключателя состояния в форме нет: он расположен между редактированием и удалением в списке.

Одинаковые категории запрещены, включая неактивные. Сравнение названий: убрать пробелы по краям, схлопнуть последовательности пробелов, сравнить без регистра. При совпадении сразу показать «Категория с таким названием уже существует» и заблокировать «Сохранить». При редактировании исключить собственный ID. На сервере повторить проверку и обеспечить уникальность при конкурентных запросах.

Категория связана с товарами по постоянному ID. Переименование должно отражаться у товаров и в поиске. Неактивная категория недоступна для назначения новому товару; существующие ссылки сохраняются. Категорию с привязанными товарами, включая неактивные, удалить нельзя. Отключение категории не должно автоматически отключать её товары.

## Доступ и границы учёта

Текущие роли API: businessUser управляет товарами, businessUser и deviceServicer читают данные в рамках доступного tenant. Для новых методов сохранить серверную проверку роли и tenant. Принадлежность к компании и права франчайзера/франчайзи требуют отдельного согласования; этот этап не расширяет доступ между компаниями.

Единица в карточке определяет единицу учёта количества. В этом этапе не меняются формулы продаж, остатков, цен, фасовок и рецептур. Поддержку дробных количеств МЛ/ГР в складских и продажных операциях проверить отдельно до использования таких единиц в рабочем учёте. КБЖУ описывает 100 г продукта и не участвует в денежном расчёте.

## Краткая последовательность для пользователя

1. Откройте «Товары» и выберите «Категории». Создайте категорию с уникальным названием.
2. Перейдите в «Каталог товаров» и нажмите «Добавить товар».
3. Укажите полное и короткое названия, штрихкод и категорию. При необходимости добавьте остальные сведения и фото.
4. Нажмите «Сохранить». При ошибке исправьте указанное поле и повторите; для отказа от изменений нажмите «Отмена».
5. Найдите товар через поиск. Для временного отключения используйте переключатель активности; для возврата выберите «Неактивные» и включите его.

Документ описывает согласованное поведение. До завершения подключения прототип сохраняет сведения в браузере; рабочий фронт должен сохранять их через API и БД. Перенос тестовых данных браузера в рабочую БД автоматически не выполняется.
